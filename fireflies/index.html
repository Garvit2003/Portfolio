Addressed to five people, owned by none. Priya reads it on her phone, thinks "yes, I know," and moves on. Nothing in the system changes on Friday, or on day 14. The item is not resolved — it is simply repeated in the next meeting.
Why not just make this email betterThis is the mechanism that is already failing. Adding reminders to it would rebuild the broken thing with a nag attached — and the brief explicitly requires working inside the product, not only through this email. I rejected "auto-assign + reminder emails" for this reason.

Three buttons, not one"Not mine" and "Wasn't a commitment" exist because extraction is sometimes wrong, and because a product that only offers "yes" is an assignment system wearing a confirmation costume. A rejected card returns the item to the room unowned — it is never silently reassigned to someone else.
Why the transcript line is shownResearch theme 5: a commitment without context becomes an unreadable task title two weeks later. Showing the sentence the person actually said makes the claim decision take two seconds instead of requiring a memory search.
The four states
Open
Claimed by a person, not yet settled.
Done
Completed — proven by a signal, or stated by the owner.
Reassigned
Accepted by a different owner.
Dropped
Deliberately let go. Counts as resolved, styled neutrally on purpose.
Resolution is not completion. Three of these four states close a commitment. Only "open" is a failure at day 14 — and a silent one is the only real failure.

No due-date enforcement, no escalation, no boardThere is no Kanban view, no subtasks, no dependency graph and no overdue-red styling. The moment this list becomes something to groom, it has become the second inbox the brief forbids.
Where the state comes from
1. Evidence, silently
A file shared, a ticket moved, a thread resolved. The owner is never asked. This is the path most commitments should take.
2. A question, once a week
Only for what the system genuinely cannot see. Batched into one digest, never one prompt per item.
3. Never by nagging
No per-item reminder emails. That is the mechanism already failing today.
Follow-up effort must go down, not up. If this screen adds work to someone's week, the feature has failed its own brief regardless of what the closure rate says.
New · feature 2

Close — one batched ask, three honest exits

Everything the system could resolve on its own has already been resolved. This is the only prompt Priya receives all week, and it arrives where she already works.

Weekly and batched, never per itemResearch theme 7: "I don't want 30 notifications every day." One digest per person per week is a hard product rule, and prompts-per-user-per-week is a guardrail metric with a cap of 2, not a number to optimise upward.
Drop is styled in slate, not redThe colour system encodes the core belief. Done is green, reassigned is blue, dropped is neutral grey — because the brief counts a deliberate drop as resolution, and a red "abandoned" badge would quietly teach people that the honest answer is the shameful one.
